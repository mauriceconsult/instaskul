# Instaskul

Maxnovate's edtech/LMS product. Course creators publish courses and tutorials;
learners enroll and pay via MTN MoMo; tutors receive payroll disbursements.

Deployed at: https://www.instaskul.com
MoMo webhook registered at: https://www.instaskul.com/api/momo/webhook

---

## Stack

- Framework: Next.js (App Router), TypeScript
- Auth: Clerk (`@clerk/nextjs`)
- Database: Prisma ORM → Neon PostgreSQL
- Payments: MTN MoMo via Platform Manager (api.maxnovate.com)
- AI: Anthropic claude-sonnet-4-6 → Maxintel fallback
- Deploy: Vercel
- Runtime: Node.js

## Architecture

### Payment flow

```
Learner clicks Enroll
  → POST /api/payments/collect        (creates Tuition, calls MoMo RequestToPay)
  → MTN delivers USSD prompt to learner's phone
  → Learner approves
  → MTN POSTs to api.maxnovate.com/api/momo/webhook (COL- prefix)
  → Manager dispatcher → handleInstaskul()
  → Tuition.isPaid = true, Enrollment created, Payroll record created
```

### Payroll flow

```
Admin: POST /api/payments/disburse
  → validates Tuition.isPaid === true
  → calls payrollService.calculatePayroll()  [10% platform + 2% tx = 88% net]
  → MoMo Transfer to tutor's MSISDN
  → MTN POSTs to webhook (PAY- prefix)
  → Payroll.momoStatus = SUCCESSFUL
```

### Reference ID prefixes (managed by Platform)

- Collections: `COL-{timestamp}-{userId.slice(0,8)}`
- Disbursements: `PAY-{timestamp}-{instructorId.slice(0,8)}`

### Journal / academic article system

Every published course can have one Journal (set by admin).
Journal → JournalArticle generated by AI using course tutorials as article sections.
Workflow: draft → submitted (by course admin) → approved/rejected (by platform admin).
On approval: `isPublic = true`, `publishedAt` set, accessible at `/api/journal/[slug]`.

Key files:
- `lib/journal/prompt-builder.ts` — builds AI prompt from course + tutorials
- `lib/journal/article-generator.ts` — Anthropic primary, Maxintel fallback
- `lib/journal/docx-builder.ts` — converts AI markdown to APA .docx
- `app/api/courses/[courseId]/journal/generate/route.ts`
- `app/api/courses/[courseId]/journal/submit/route.ts`

## Database — key models

- `Course` — has `journal Journal?` (one-to-one)
- `Content` — tutorials belonging to a course (ordered by `position`)
- `Tuition` — payment record per enrollment (momoReferenceId, momoStatus, isPaid)
- `Payroll` — disbursement record per tuition (grossAmount, platformFee, netPayout)
- `Enrollment` — created atomically with Payroll on webhook SUCCESSFUL
- `Journal` — one per course, holds context/thesis for AI article generation
- `JournalArticle` — generated article with slug, isPublic, publishedAt, excerpt

## Fee structure

Source of truth: `payrollService.calculatePayroll(tuitionAmount)`:
- Gross: course price
- Platform fee: 10%
- Transaction fee: 2%
- Net to tutor: 88%

Never compute fees inline. Always use `payrollService.calculatePayroll()`.

## AI integration

Journal article generation: if Anthropic fails (rate limit, billing), automatically
delegates to Maxintel (`/platform/generate`). Never let a generation failure
surface to the course admin without attempting the fallback first.

---

## Do not

- Do not trust client-supplied `amount` in payment routes — always read from DB Course.price
- Do not create Enrollment without first confirming Tuition.momoStatus === 'SUCCESSFUL'
- Do not run `prisma migrate reset` — destroys enrollment and payment data
- Do not commit `.env.local`
- Do not compute fees inline — always use `payrollService.calculatePayroll()`
- Do not call `disburse` on a Tuition where `isPaid !== true`
